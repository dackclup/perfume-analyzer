# หลักการและวิธีทำงานกับ AI ของ Lauren Tan (poteto)

> สรุปเฉพาะวิธีคิดและวิธีทำงานกับ AI ของเธอ ข้อมูลถึงตุลาคม 2026
> Lauren Tan (GitHub/X: poteto) ทำ Grok Bot และ Cursor ที่ SpaceXAI อยู่ทีม React Core และเคยทำ React Compiler ที่ Meta
> เธอรวมหลักทั้งหมดไว้ในปลั๊กอินโอเพนซอร์สชื่อ **pstack** (cursor/plugins)

---

## 1. แก่นความคิด

- **คอขวดคือการตรวจงาน** ไม่ใช่การให้ AI เขียนหรือสร้างงาน
- **agent เหมือนพนักงานใหม่ที่ความจำเสื่อมตลอดเวลา** จึงต้องติดอาวุธให้ด้วยกฎ skill เครื่องมือ และหน่วยความจำที่เขียนลงไฟล์ ไม่ใช่ด้วย prompt ที่ยาวขึ้น
- **เชื่อใจก่อน แล้วค่อยขยาย** ทำงานกับ agent ทีละตัวจนเชื่อใจผลงานได้ แล้วค่อยให้ทำหลายงานพร้อมกัน ถ้ายังไม่เชื่อใจแล้วเปิดหลายตัวก็เปลืองเปล่า
- **เชฟร้านมิชลิน ไม่ใช่เจ้าของโรงงาน** คนยังต้องรับผิดชอบทุกงานที่ออกไป

---

## 2. หลักการหลัก 8 ข้อ

| # | หลักการ | ความหมาย |
|---|---|---|
| 1 | **Prove It Works** | ตรวจกับผลจริง ไม่ใช่ตัวแทนอย่าง "คอมไพล์ผ่าน" หรือ "AI บอกว่าเสร็จแล้ว" |
| 2 | **Build the Lever** | ทำครั้งแรกด้วยมือเพื่อเรียนรู้ แล้วสร้างสคริปต์ที่รันซ้ำได้ เปลี่ยน "เชื่อฉันเถอะ" เป็น "รันนี่ดู" |
| 3 | **Encode Lessons in Structure** | ถ้าต้องสั่งเรื่องเดิมเป็นครั้งที่สอง ให้เปลี่ยนเป็นการตรวจอัตโนมัติแทนการเขียนข้อความเพิ่ม |
| 4 | **Laziness Protocol** | เลือกการเปลี่ยนแปลงที่เล็กที่สุดที่แก้ปัญหาได้ ลบของเก่าก่อนเพิ่มของใหม่ |
| 5 | **Sequence Work into Verifiable Units** | แบ่งงานเป็นหน่วยเล็ก แต่ละหน่วยจบด้วยการตรวจ |
| 6 | **Guard the Context Window** | ส่งงานก้อนใหญ่ให้ subagent แล้วเก็บไว้แค่สรุปในเธรดหลัก |
| 7 | **ความเป็นอิสระมีขอบเขต** | งานที่ย้อนกลับได้ให้ทำเลย งานที่ย้อนกลับไม่ได้ต้องหยุดถามคนก่อนเสมอ |
| 8 | **รับผิดชอบงานของ subagent** | อ่านผลเอง สรุปเอง อย่าส่งต่อคำว่า "เสร็จแล้ว" ของมันไปตรงๆ |

## 3. การวางแผน

- **วางแผนด้วยต้นแบบจริงแทนแผนบนกระดาษ** เธอมองว่าการทำต้นแบบก็คือการวางแผน
- ถ้าทดลองแล้วรู้คำตอบได้ ให้ผลทดลองเป็นตัวตัดสิน
- เก็บคำถามที่ต้องถามคนไว้สำหรับเรื่อง **รสนิยม** เท่านั้น
- ใช้แผนหลายเฟสหลังจากออกแบบลงตัวแล้วเท่านั้น

---

## 4. การสั่งงาน (prompt)

- พูดเป้าหมายตรงๆ ไม่ต้องมีพิธีหรือคำเกริ่น
- prompt ที่ดีมี 4 ส่วน:

```
เป้าหมาย:            (อยากได้อะไร)
เสร็จเมื่อ:            (เงื่อนไขที่ตรวจได้ ผ่าน/ไม่ผ่าน)
หลักฐานที่อยากเห็น:   (แสดงผลอะไรให้ดูว่าทำได้จริง)
สิ่งที่รู้อยู่แล้ว:       (ข้อมูล/ข้อจำกัดที่มี)
```

- **ให้ AI เล่าโจทย์ด้วยคำพูดของตัวเองก่อนลงมือ** เพื่อเช็กว่าเข้าใจตรงกัน
- **ถ้าต้องแก้ทิศ ให้เอ่ยชื่อหลักการ** แทนการอธิบายยาว เพราะ agent อ่านกฎเต็มไว้แล้ว ชื่อเดียวจึงแก้ได้แม่นกว่า

## 5. หน่วยความจำและ context

- **ไฟล์กฎ (CLAUDE.md) สั้นและเป็นข้อๆ** ให้อ่านก่อนเริ่มงาน และเขียนเพิ่มหลังพลาดหรือถูกแก้
- **คลังบทเรียน** เก็บหนึ่งหัวข้อต่อหนึ่งไฟล์ ให้ AI อ่านตอนเริ่ม และเขียนเพิ่มเมื่อเรียนรู้อะไรใหม่
  - **reflect**: สรุปบทเรียนหลังจบงาน (ขั้นนี้ขั้นเดียวให้คุณค่าส่วนใหญ่แล้ว)
  - **meditate**: ทบทวนแล้วตัดเนื้อหาที่ล้าสมัยออกเป็นระยะ
- **แผนที่ (feature map)** บอกว่าอะไรอยู่ตรงไหน เข้าถึงอย่างไร และมีกับดักอะไร และควรอัปเดตสม่ำเสมอ
- **งานเดิมคือหน่วยความจำ** AI จะลอกแบบของที่มีอยู่ จึงต้องเก็บกวาดของเสียก่อนที่จะถูกลอกต่อ (บทบาท "คนสวน")

---

## 6. การตรวจงาน

**ห้าชั้นของการแก้ความผิดพลาด** (จากแข็งแรงที่สุดไปอ่อนที่สุด)
1. ทำให้ผิดไม่ได้ตั้งแต่โครงสร้าง
2. ตรวจอัตโนมัติ (lint, CI, สคริปต์)
3. กฎและ skill
4. คนรีวิวตามคู่มือ
5. ทดสอบพิสูจน์ผล (พิสูจน์ว่าถูก แต่ไม่ได้พิสูจน์ว่าดีหรือเร็ว)

**วิธีเสริม**
- **ให้โมเดลอื่นรีวิว** ห้ามโมเดลเดียวกันรีวิวงานตัวเอง
- **ทดสอบ skill (evals)** ให้หลาย agent ทำโจทย์เดียวกัน ตั้งเกณฑ์ให้คะแนน แล้วใช้โมเดลอื่นเป็นผู้ตัดสินเพื่อลดอคติ
- **บันทึกการตัดสินใจ** เป็นตาราง (เวลา, เฟส, การตัดสินใจ, เหตุผล, หลักฐาน, ผลลัพธ์)

## 7. งานหลาย agent และงานยาว

- แบ่งงานเป็นชิ้นให้ agent หลายตัว หรือทำหลายเวอร์ชันแล้วคัดตัวที่ดีที่สุด
- **สัญญางานข้ามคืน** ต้องมี 3 อย่าง:
  1. เงื่อนไขว่าเสร็จที่ตรวจได้
  2. พื้นที่ทำงานแยกจากงานหลัก
  3. บันทึกการตัดสินใจไว้ตรวจตอนเช้า
- **หนึ่งรอบ = หนึ่งการเปลี่ยน + หนึ่งการตรวจ + หนึ่งบรรทัดบันทึก**
- **ระยะเวลาไม่ใช่เงื่อนไขว่าเสร็จ** ("ทำไปสองชั่วโมง" ไม่ได้แปลว่าเสร็จ)
- ระบบอัตโนมัติบนคลาวด์ทำได้ทั้งวงจร ตั้งแต่รับงาน คัดแยก ลองทำให้ปัญหาเกิดซ้ำ แก้ ไปจนถึงส่งผลพร้อมหลักฐานก่อน/หลังให้คนอนุมัติ

---

## 8. เครื่องมือ

- ใช้หลายโมเดลตามจุดแข็งของแต่ละตัว และปรับได้ตามงาน
- ใช้ agent บนคลาวด์และงานอัตโนมัติแบบตั้งเวลา
- เธอรวมหลักทั้งหมดเป็น skill ใน **pstack** ซึ่งชุมชนนำไปพอร์ตใช้กับ Claude Code และ Codex ด้วย (พอร์ตไม่ได้ทำโดยเธอ)
